## GitHub Actions

Workflow: `.github/workflows/deploy-reg-ru.yml`. Публикует только `index.html`, `styles.css` и файлы в `assets/`. Никакой сборки npm/PHP не требуется.

Secrets в GitHub (значения никогда не записывать в репозиторий):

- `REG_FTP_SERVER`: проверенное имя сервера (не IP для TLS).
- `REG_FTP_USERNAME`: выделенный пользователь ВСЗ.
- `REG_FTP_PASSWORD`: пароль выделенного пользователя.

Variable `REG_DEPLOY_MODE`:

- отсутствует или `off`: только локальная проверка пакета, **никакого FTP**;
- `dry-run`: подключение по проверенному FTPS и вывод списка файлов без изменений на сервере;
- `live`: выгрузка статических файлов по FTPS. Срабатывает при новых коммитах в `main` и ручном запуске из Actions.

Из Pull Request никогда не выполняется соединение с FTP и не используются секреты публикации. TLS проверяется, данные идут через защищённый канал. Запись возможна только в пределах домашней директории FTP-пользователя. **Удаление файлов на сервере запрещено**; старые неиспользуемые файлы могут оставаться, их очистку нужно согласовывать отдельно.

## Порядок первого запуска

1. Объединить PR с workflow только после review. При `REG_DEPLOY_MODE=off` публикация после merge **не запустится**.
2. Переключить Variable `REG_DEPLOY_MODE=dry-run` и выполнить **Actions → Build and publish VSZ to REG.RU → Run workflow → main**.
3. Проверить в логах `DRY RUN: PASS` и отсутствие операций записи/удаления. Если TLS или FTP-доступ отказали — не переводить в live.
4. После успешного dry-run и разрешения владельца выставить `REG_DEPLOY_MODE=live` и вручную запустить workflow из `main`.
5. В ispmanager проверить `index.html`, `styles.css`, `assets/` непосредственно в `/www/vsp-kirov.ru/`. Убедиться, что `sf676.ru` не изменён.
6. Отдельно проверить веб-сайт через IP с принудительным Host/SNI, получить доверенный SSL для apex/www, затем переключить только две необходимые A-записи в Beget. MX, SPF, DKIM, DMARC, NS, `b24` и другие записи не менять.
7. После переключения проверить публичный HTTPS, www, телефон, e-mail, изображения и DNS; публикации будущих PR → main продолжатся автоматически, пока `live`.

При инциденте установить `REG_DEPLOY_MODE=off`, остановив последующие публикации. Возврат DNS на Beget допустим только после проверки, что прежний хостинг исправен.
